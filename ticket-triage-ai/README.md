# ticket-triage-ai
Учебный проект одного исполнителя. По теме и тексту заявки диспетчер получает две рекомендации и может подтвердить или исправить каждую. Исторический CSV не предоставлен. Деморежим использует исключительно синтетические шаблоны. Качество на реальных обращениях и выполнение критериев приёмки пока неизвестны.

## Продолжение существующего проекта
Сохранены исходные документы о MVP, рисках, backlog и данных, а также искусственный JSON-пример. Код добавлен к этой основе. Статусы и контракты приведены в соответствие с текущей реализацией. См. [backlog](docs/backlog.md) и [схему](docs/data-schema.md).

Папки `ml/`, `api/`, `ui/` и `tests/` сохранены. Рабочие файлы находятся в корне для простого запуска notebook. HTTP API, графическая форма и интеграция с почтой остаются запланированными. Полный MVP исходного практикума ещё требует этих шагов и проверки на реальных данных.

При импорте старые приоритеты `low`, `medium`, `high`, `critical` и `средний` приводятся к `низкий`, `стандартный`, `высокий`, `критический`. Старый JSON-пример остаётся иллюстрацией одной записи. Для обучения требуется CSV со всеми классами.

## Быстрый старт
Команды выполняются из папки проекта. Проверено на Windows с Python 3.13.5. Для PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe -m ipykernel install --user --name ticket-triage-ai --display-name "Ticket triage AI"
.\.venv\Scripts\python.exe -m jupyterlab experiment.ipynb
```

В Jupyter выберите ядро **Ticket triage AI**, затем **Run → Run All Cells**. По умолчанию создаются 384 синтетических обращения, 64 из них резервируются на тест. Notebook печатает каталог запуска в первой ячейке. JSON, таблицы и модель сохраняются в отдельном подкаталоге `runs/SYNTHETIC/` или `runs/historical/`. Новый запуск получает отдельный каталог.

## Обучение на историческом CSV
1. Подготовьте локальный обезличенный CSV в UTF-8, разделитель — запятая. Путь по умолчанию для размещения — `data/tickets.csv`. Заголовок: `id,subject,text,department,priority`. Также принимаются `ID,тема,текст,ответственное подразделение,приоритет`. ID читается строкой с сохранением ведущих нулей. Исключите подписи, контакты и добавленные после маршрутизации служебные пометки.
2. В первой ячейке задайте `DATA_CSV = Path("data/tickets.csv")`. Если 2 000 ID уже отложены, обязательно укажите их через `TEST_IDS_CSV = Path("data/test_ids.csv")` (столбец `id`). При отсутствии списка программа один раз определяет состав теста для заданных данных и seed. Сортировка по ID делает разбиение независимым от порядка строк.
3. Выполните все ячейки. При ошибке схемы, размера выборки или межвыборочных дублях исправьте источник до обучения. При наличии связанных переписок проверьте их принадлежность одной выборке отдельно.
4. Изучите таблицы сравнения, матрицы и пропуски критических заявок. Критерии применяются к финальной паре TF-IDF-моделей. Поле `acceptance` в деморежиме равно `null`.

## Работа диспетчера
После запуска notebook подставьте выведенный путь к модели:

```powershell
.\.venv\Scripts\python.exe operator_cli.py "runs/SYNTHETIC/<каталог запуска>/model.joblib"
```

Загружайте только модели, созданные своим запуском. Введите тему и описание. Для каждого поля отображаются рекомендация, вероятность выбранного класса и допустимые метки. Нажмите Enter для подтверждения или введите метку из списка. Значение вероятности не калибровано. За итоговое решение отвечает диспетчер.

Каждый вызов обрабатывает одну заявку. Журнал `private/decisions.sqlite` хранит локальный номер, время, режим данных, отпечаток модели, обе рекомендации с вероятностями и обе финальные метки. Тема и описание в журнал не записываются. При прерывании ввода рекомендация остаётся без финального решения. Для отдельного журнала добавьте `--db private/demo.sqlite`.

## Файлы и отчёты
- `docs/ml_task.md` — постановка, протокол и критерии проверки.
- `triage.py` — схема, разбиение, синтетические примеры, обучение и оценка.
- `experiment.ipynb` — воспроизводимый эксперимент с отображением отчётов.
- `operator_cli.py` — интерфейс и журнал решений.
- `test_smoke.py` — синтетические проверки схемы, размеров, отсутствия утечки словаря, матриц ошибок и действий оператора.
- `split.csv`, `train_counts.csv` — состав выборок по ID и частоты меток обучения.
- `validation.csv`, `test_metrics.csv`, `matrix_*.csv` — подбор C, итоги теста, четыре матрицы ошибок.
- `missed_*.csv` — пропуски критического класса с локальными ID, подразделениями и метками, без исходного текста.
- `run.json`, `model.joblib` — режим, seed, хеш нормализованных данных, выбранные параметры, результат проверки и модель для диспетчера.

Публикуйте исходный notebook с очищенными выводами. Датасеты, журнал, отчёты и модели остаются локально: ID и словарь модели могут содержать сведения из источника.
