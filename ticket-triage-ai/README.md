# ticket-triage-ai
Учебный помощник диспетчера поддержки. По теме и тексту заявки рекомендует подразделение и приоритет, показывает уверенность, позволяет подтвердить или изменить рекомендации и сохраняет прогноз вместе с итоговым решением.

В репозитории находится собственный CSV из 12 000 синтетических заявок. Он создан по шаблонам для учебной проверки и помечен SYNTHETIC. Фактического исторического датасета пока нет. Метрики на синтетических шаблонах не подтверждают качество на реальных обращениях.

## Начало работы
Распаковать или клонировать репозиторий и открыть терминал в папке ticket-triage-ai. В PowerShell выполнить команды установки.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m ipykernel install --user --name ticket-triage-ai --display-name "Ticket triage AI"
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe -m jupyterlab
```

В Jupyter выбрать ядро Ticket triage AI. Сначала открыть data_checks.ipynb и выполнить Run → Run All Cells. Затем выполнить experiment.ipynb. Оба notebook по умолчанию читают data/synthetic/tickets_synthetic.csv, который уже включён в репозиторий. Для повторного создания CSV выполнить следующую команду.

```powershell
.\.venv\Scripts\python.exe create_synthetic_csv.py
```

Генератор воспроизводит 12 000 строк с seed 42 и обновляет метаданные с SHA-256. Код и notebook проверены в имеющейся среде Python 3.13.5. Установка в отдельном чистом окружении остаётся задачей QA.

## Проверка данных
data_checks.ipynb выводит shape, названия и типы столбцов, первые строки, null, пустые значения и их доли, уникальность ID, повторяющиеся ID и строки, дубли объединённых текстов, короткие тексты и неизвестные метки. Справочник синтетических подразделений берётся из генератора. Для реальных данных его нужно согласовать и задать в EXPECTED_DEPARTMENTS. При None проверка неизвестных подразделений отмечается невыполненной.

Проверки сохраняют строки и исходный CSV. Порог короткого текста составляет 20 символов и используется для диагностики. Критические заявки сохраняются независимо от частоты. Правила преобразований описаны в [отчёте проверки](docs/data_audit.md), фактические проверки поставки перечислены в [verification.md](docs/verification.md).

## Обучение и оценка
Две независимые задачи используют X из темы и текста, y из подразделения и приоритета. Для каждой сравниваются наиболее частый класс и TF-IDF + Logistic Regression. Словарь и IDF обучаются только на train. Значение C выбирается между 0.5 и 2.0 на validation. Для набора из 12 000 строк выполняется разбиение 8 000 / 2 000 / 2 000 с seed 42 и стратификацией по приоритету. Тест используется после фиксации моделей.

Macro F1 и Weighted F1 считаются по обеим задачам, отдельно recall критического приоритета. Сохраняются четыре матрицы ошибок и ID пропущенных критических заявок. Для исторических данных критерии составляют Macro F1 каждой задачи не менее 0,72 и recall критических не менее 0,80. Для синтетики mode=SYNTHETIC и acceptance=null независимо от числовых метрик.

Для исторического эксперимента положить обезличенный CSV локально в data/raw/, указать DATA_CSV в обоих notebook и согласованный EXPECTED_DEPARTMENTS в проверке данных. Формат описан в [data-schema.md](docs/data-schema.md). Если тест уже отложен, передать CSV со столбцом id через TEST_IDS_CSV. Все 2 000 ID должны входить в источник. При отсутствии списка тест воспроизводимо формируется по seed и сортированным ID. Программа ожидает 12 000 строк после согласованной подготовки. Дефекты и изменение объёма требуют явного решения перед обучением.

Только subject и text используются как признаки. ID, метки и data_origin в признаки не попадают. Старые приоритеты low/medium/standard/high/critical и средний поддерживаются преобразованием. Локальный run.json содержит режим, seed, выбранные параметры и хеш нормализованных данных.

## Работа диспетчера
Notebook печатает путь каталога запуска. Подставить его в команду ниже.

```powershell
.\.venv\Scripts\python.exe operator_cli.py "runs/SYNTHETIC/<каталог запуска>/model.joblib"
```

Загружать только модели собственного запуска. Ввести тему и описание. Для каждого поля отображаются рекомендация, вероятность класса и допустимые метки. Enter подтверждает рекомендацию, введённая метка исправляет её. Вероятности модели не калиброваны. Итог утверждает диспетчер.

Журнал private/decisions.sqlite хранит локальный ID, время, режим, отпечаток модели, исходные рекомендации с вероятностями и финальные метки. Тексты заявок не сохраняются. При прерывании ввода рекомендация может остаться без подтверждения. Для отдельного журнала использовать --db private/demo.sqlite. Подробности описаны в [mvp.md](docs/mvp.md).

## Локальные результаты и публикация
Отчёты EDA и эксперимента находятся в runs/SYNTHETIC/ или runs/historical/. Сохраняются split.csv, train_counts.csv, validation.csv, test_metrics.csv, matrix_*.csv, missed_*.csv, run.json и model.joblib. Первичные данные, базы, модели и отчёты реального прогона остаются локально. В git разрешён только конкретный синтетический CSV. Перед коммитом проверить содержимое файлов и очистить выводы notebook. Подробный [порядок загрузки](docs/upload-guide.md) включает создание скрытого .gitignore через редактор GitHub.
