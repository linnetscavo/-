# План оценки
Реализованы два независимых классификатора и два baseline для каждой цели. Подробный протокол и критерии находятся в [ml_task.md](ml_task.md), запуск в [README](../README.md).

Из 12 000 записей отложены по плану 2 000 для теста. Оставшиеся делятся на 8 000 train и 2 000 validation. Существующие ID теста передаются через TEST_IDS_CSV. TF-IDF обучается только на train. Выбор C производится по validation, после фиксации двух моделей оценивается тест. При расхождении фактического размера с условием программа останавливается.

Macro F1 и Weighted F1 считаются для обеих целей. Для принятия требуется Macro F1 каждой задачи не менее 0,72 и recall критических не менее 0,80. Weighted F1 служит отчётной метрикой. Сохраняются матрицы ошибок и список пропущенных критических ID. Разбор причин выполняется по локальному обезличенному источнику.

Реальных результатов пока нет. Синтетические проверки подтверждают работоспособность сценария. Деморежим всегда сохраняет acceptance=null.

Цель первого практикума для будущего API составляет не более 2 секунд на заявку. После реализации записать оборудование, размер входа, прогрев, среднее и максимальное время. Проверка API и подтверждение этого порога ожидают реализации.

Собственный синтетический CSV из 12 000 строк включён в data/synthetic/. На нём воспроизводятся части 8 000 / 2 000 / 2 000. Автоматическая маркировка сохраняет acceptance=null. Первичная проверка данных находится в data_checks.ipynb и docs/data_audit.md.
