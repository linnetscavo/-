# Схема данных
По условию ожидаются 12 000 исторических заявок. Реальная выгрузка пока отсутствует.

| Поле | Тип | Проверка |
|---|---|---|
| id | строка | Уникальный непустой обезличенный ID |
| subject | строка | Вместе с text содержит непустой текст |
| text | строка | Вместе с subject содержит непустой текст |
| department | строка | Непустая метка, справочник определяется источником |
| priority | строка | низкий, стандартный, высокий, критический |

CSV читается в UTF-8 с запятой. Русские заголовки ID, тема, текст, ответственное подразделение и приоритет поддерживаются. Отсутствующие значения темы или текста заменяются пустой строкой. ID и метки обязательны.

Для совместимости с первым практикумом импорт преобразует low в низкий, medium и средний в стандартный, high в высокий, critical в критический. Регистр и крайние пробелы приоритета нормализуются. Неизвестные метки приводят к ошибке. Для исторического обучения нужны все четыре приоритета и хотя бы два подразделения.

Только тема и текст входят в признаки. ID сохраняется для учёта. Метки используются как две независимые цели. `data/examples/ticket.json` содержит исходный искусственный пример с medium. Подразделение it_support вымышлено.

Перед обучением проверить качество разметки, распределения, дубликаты и связанные переписки. Автоматическая проверка находит повторяющиеся ID и пересечение нормализованных текстов между выборками. Семантические дубли требуют ручного анализа. Реальные выгрузки и отчёты хранятся локально в игнорируемых каталогах. В git допускаются вручную созданные искусственные примеры и явно помеченный синтетический CSV генератора проекта.

Собственный синтетический CSV также содержит data_origin со значением SYNTHETIC. Это служебная маркировка, она исключается из признаков. Генератор определяет пять учебных подразделений. Для исторического CSV справочник необходимо согласовать отдельно.
