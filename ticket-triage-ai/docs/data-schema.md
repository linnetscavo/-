# Схема заявки

Источник по условию — 12 000 исторических заявок. Таблица задаёт предлагаемые внутренние имена полей; при импорте сопоставить их с колонками выгрузки.

| Поле | Имя в проекте | Тип | Обязательность | Источник и правило |
|---|---|---|---|---|
| ID | `id` | строка | всегда | Историческая система; для новой заявки создаётся приложением. Уникальный обезличенный идентификатор |
| Тема | `subject` | строка | всегда | История / ввод диспетчера; не пустая после удаления пробелов |
| Текст | `text` | строка | всегда | История / ввод диспетчера; не пустой после удаления пробелов |
| Подразделение | `department` | строка | для обучения | Историческая метка; принадлежит согласованному справочнику |
| Приоритет | `priority` | строка | для обучения | Историческая метка; один из согласованных классов |

На вход прогноза передаются только `subject` и `text`; метки не должны попадать в признаки модели. ID не используется как признак.

## Предварительные классы приоритета

| Значение | Отображение |
|---|---|
| `low` | Низкий |
| `medium` | Средний |
| `high` | Высокий |
| `critical` | Критический |

Эти четыре класса предложены для заготовки: на доступных слайдах полного перечня нет. Перед подготовкой данных проверить фактические значения и согласовать отображение. Подразделение `it_support` в примере вымышлено и не задаёт полный справочник.

## Искусственный пример исторической записи

```json
{
  "id": "demo-001",
  "subject": "Не открывается учебный портал",
  "text": "При открытии тестового портала отображается пустая страница.",
  "department": "it_support",
  "priority": "medium"
}
```

Этот пример также лежит в `data/examples/ticket.json`. Он не является обучающей выборкой.

## Проверка перед обучением

Проверить число записей, уникальность ID, пустые темы и тексты, дубликаты, неизвестные метки и распределение обоих целевых полей. Отдельно посчитать критические заявки. Сомнительные метки разобрать вручную; правила исключения строк записать в отчёт.

Реальные имена, телефоны, адреса электронной почты, учётные данные и другие идентификаторы не должны попадать в git или публичные отчёты. Исходную выгрузку хранить вне репозитория либо локально в игнорируемой папке `data/raw/`; после обезличивания данные также не публиковать. Публикуемые примеры создавать вручную.
