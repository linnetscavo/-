# Локальный git и публикация

Стартовые файлы подготовлены локально. Удалённый репозиторий не создан: в этой сессии нет подключённого инструмента создания репозиториев GitHub/GitLab. До публикации резервный вариант — локальная папка проекта и ZIP-архив.

## 1. Создать локальный репозиторий и первый коммит

Откройте терминал в папке `ticket-triage-ai`. Если папка `.git` уже есть, повторять `git init` не нужно.

```sh
git init -b main
git status --short
git add .
git diff --cached --stat
git diff --cached
git commit -m "Initial project scaffold"
```

Перед коммитом просмотрите подготовленные файлы: только документы и искусственные примеры. Не добавляйте игнорируемые файлы через `git add -f`.

Если git просит имя и почту, настройте их для этого репозитория. Подставьте свой псевдоним и выбранный адрес для коммитов (при желании — приватный адрес, выданный платформой):

```sh
git config user.name "YOUR_NAME"
git config user.email "YOUR_COMMIT_EMAIL"
```

Затем повторите коммит. Эти значения попадают в историю коммитов; не используйте случайные чужие адреса.

## 2. Создать пустой проект на платформе

В своём аккаунте GitHub или GitLab создайте пустой репозиторий/проект с именем `ticket-triage-ai`. Не добавляйте README, `.gitignore` и лицензию на сайте: локальные файлы уже подготовлены. Выберите видимость согласно требованиям учебного курса. Скопируйте HTTPS- или SSH-адрес созданного репозитория.

## 3. Связать локальный проект и отправить

В следующей команде замените `REMOTE_URL` скопированным адресом без токенов и паролей:

```sh
git remote add origin REMOTE_URL
git push -u origin main
```

Используйте авторизацию через менеджер учётных данных или настроенный SSH. Не записывайте токен в файлы проекта или адрес `origin`. Если `origin` уже существует, сначала проверьте его командой `git remote -v`, а не добавляйте второй.

## Если доступа к платформе пока нет

Сохраните локальный проект и архив как резервный вариант. Организационная задача автора проекта: получить доступ, создать пустой удалённый репозиторий и отправить первый коммит. Готово, когда README и папки видны на платформе, а ссылку можно передать преподавателю.
