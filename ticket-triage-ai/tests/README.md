# План проверок

Автоматических тестов пока нет: приложения ещё нет. После реализации проверить:

1. Валидные тема и текст дают подразделение и приоритет, каждое с уверенностью от 0 до 1.
2. Подтверждение без изменений сохраняет прогноз и такое же итоговое решение.
3. Изменение только подразделения, только приоритета или обоих полей сохраняет выбор, не меняя исходный прогноз.
4. После повторного чтения доступны оба решения, ID заявки, версия модели и время сохранения.
5. Пустой ввод, пробелы, неверный тип и неизвестные метки обрабатываются понятной ошибкой.
6. Недоступность модели и ошибка записи не показываются как успешный прогноз или сохранение.
7. Ответ API для одной заявки занимает ≤ 2 секунд; условия и результаты замеров записаны.
8. На отдельном тесте из 2 000 заявок рассчитаны метрики и проверены пороги из `../docs/evaluation.md`.
9. Приложение запускается по будущей инструкции в чистом окружении.

Для функциональных тестов использовать искусственные данные. Для оценки качества — отдельную локальную тестовую выборку, исключённую из git.
